# Подключить плагин к Exterminatus: пошагово

Инструкция для одного плагина B&A community. Её можно выполнить руками или
отдать как задание Claude или Codex, открытому в проекте плагина. Справочник
по API — [PLUGIN_GUIDE.md](PLUGIN_GUIDE.md), рабочий пример —
[examples/hello_plugin](../examples/hello_plugin).

Цель: каждый пункт меню и каждая кнопка плагина описаны через
`BACommunity::Terminal.command`, и плагин работает и с терминалом, и без него.

## Что взять из репозитория Exterminatus

- `src/exterminatus/terminal_bridge.rb` — мост, копируется в плагин без
  изменений;
- `docs/PLUGIN_GUIDE.md` — справочник;
- `examples/hello_plugin/hello_plugin/main.rb` — образец.

## Шаги

1. **Опись.** Выпишите все пункты меню, кнопки панелей и пункты контекстного
   меню плагина. Для каждого укажите:
   - что делает;
   - какие значения спрашивает (окно, `UI.inputbox`, свой диалог);
   - нужны ли клики в модели (свой `Tool`);
   - что берёт из выделения.

   Опись положите в описание задачи или PR.

2. **Мост.** Скопируйте `terminal_bridge.rb` в папку плагина рядом с `main.rb`.
   В начале `main.rb` подключите его:
   `Sketchup.require(File.join(__dir__, 'terminal_bridge'))`. Файл не правьте.

3. **Имена.** Каждому пункту дайте `id`:
   - английский CamelCase, называет действие: `PathCopy`, `WallByLines`,
     `RalFan`;
   - не совпадает с командами SketchUp (их список — `Commands SketchUp` в
     терминале).

   Добавьте:
   - `keywords:` — 2–5 русских слов, по которым его будут искать;
   - `description:` — одну английскую фразу;
   - `examples:` — 1–2 строки, если у команды есть параметры.

4. **Простые пункты** (открыть окно, включить инструмент, действие без
   параметров) замените на:

   ```ruby
   T.command(id: 'RalFan', plugin: 'RALNCS', description: 'Open the RAL/NCS color fan',
             keywords: 'цвет веер ral', menu: 'Extensions/RALNCS', menu_text: 'Color Fan',
             toolbar: 'RALNCS', icon: File.join(__dir__, 'icons', 'fan.svg')) { Fan.show }
   ```

   Старые `UI::Command.new`, `menu.add_item`, `toolbar.add_item` для этого
   пункта удалите: меню и кнопку теперь строит `command`. Текст пункта меню
   сохраните прежним (`menu_text:`), иконку — прежней (`icon:`).

5. **Пункты с окном параметров** (`UI.inputbox` или свой диалог с полями)
   переведите на `params:`. Каждое поле окна становится параметром:
   - основные — с вопросом (`prompt: true`, по умолчанию);
   - второстепенные — опциями (`prompt: false`).

   Длины пишите как `500.mm`. Блок команды получает `args` и вызывает ту же
   функцию, что раньше вызывало окно. Окно без терминала мост покажет сам.
   Если старое окно было богаче (превью, картинки), оставьте его в
   `fallback:`.

6. **Пункты с кликами в модели** (свой `Tool`) — два пути:
   - **лучше:** точки — параметры `type: :point` с `base:` и `preview:`.
     Терминал сам даёт клики, привязки, ввод `@dx,dy`, Esc и Enter. Старый
     инструмент передайте в `fallback:` для работы без терминала;
   - **быстрее:** оставьте свой `Tool`. Его шаги пусть пишут приглашение
     через `Terminal.prompt(..., tool: true)`, а в `deactivate` —
     `Terminal.prompt(nil)` (PLUGIN_GUIDE, раздел 7).

7. **Выделение.** Если команда работает с выделением, сделайте его параметром
   `type: :selection` с `kinds:` и `label:` («Select walls»), а не проверкой
   «ничего не выделено» внутри. Тогда с пустым выделением терминал попросит
   выделить.

8. **Результат.**
   - Верните `{ ok: true, message: '...' }` или строку.
   - При отказе верните `{ ok: false, message: 'почему' }`, а не
     `UI.messagebox`.
   - Если команда создаёт объекты не в текущем контексте, добавьте
     `created: [...]`.
   - Шаг отмены — `start_operation` / `commit_operation`, как раньше.

9. **Проверка** (PLUGIN_GUIDE, раздел 10):
   - `PluginCheck <плагин>` без замечаний или с объяснимыми;
   - каждая команда работает набором, кликом по пункту меню и кликом по
     кнопке;
   - с отключённым Exterminatus пункты меню работают.

10. **Документы плагина.** В README добавьте раздел «Терминал» с таблицей
    команд (`id`, синонимы, что спрашивает). В CHANGELOG — запись новой
    версией.

## Чек-лист

- [ ] `terminal_bridge.rb` скопирован без изменений и подключён первым
- [ ] каждый пункт меню и каждая кнопка описаны через `T.command`, старые
      `UI::Command` для них удалены
- [ ] `id` — английский CamelCase, не занят; `keywords` по-русски; `description` по-английски
- [ ] окна параметров превращены в `params`; длины по умолчанию с `.mm`
- [ ] клики в модели — параметры `:point` (или `Terminal.prompt` в своём инструменте)
- [ ] выделение — параметр `:selection` с `kinds` и `label`
- [ ] блок возвращает `{ ok:, message: }`; отказ объясняет причину
- [ ] `PluginCheck` чистый
- [ ] проверено без терминала
- [ ] README и CHANGELOG обновлены

## Задание для Claude или Codex в проекте плагина

Скопируйте в проект плагина файлы `terminal_bridge.rb`, `docs/PLUGIN_GUIDE.md`
и этот файл. Затем дайте агенту такой текст:

> Подключи этот плагин к терминалу Exterminatus по docs/INTEGRATE.md
> (справочник — docs/PLUGIN_GUIDE.md). Сначала сделай шаг 1 — опись пунктов
> меню и кнопок — и покажи её мне. Код не меняй, пока я не подтвержу имена
> команд. Поведение плагина без терминала должно остаться прежним.
