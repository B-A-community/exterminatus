# Релизы наших плагинов и обновление из Exterminatus

Exterminatus ставит и обновляет плагины B&A community прямо из SketchUp:
Extensions → Exterminatus → **Plugin Updates…** или команды в терминале.

Чужие плагины он не трогает. В списке только плагины из публичных
репозиториев организации **B-A-community** на GitHub. Новые плагины попадают
в список сами, как только у них выходит релиз 1.0.

В код плагинов ничего добавлять не нужно. Exterminatus берёт:

- установленную версию — из Extension Manager (`SketchupExtension#version`);
- язык сборки — из `<папка плагина>/lang.rb` (`LANG = 'ru'`);
- новые версии — из релизов GitHub.

## Как выпустить новую версию плагина

Так же, как сейчас:

1. Поднимите версию в загрузчике плагина (`ex.version` / `VERSION`).
2. Соберите пакеты, как обычно: `build.ps1` или `tools/build_rbz.ps1`.
3. Создайте релиз на GitHub в репозитории `B-A-community/<плагин>`:
   - тег `vX.Y` (например `v1.2`);
   - ассеты по образцу `<имя>-<версия>-rus.zip` и `<имя>-<версия>-eng.zip`.

   Внутри zip лежит `.rbz` (PDF рядом можно оставить). Можно прикладывать и
   сам `.rbz` с теми же суффиксами: `<имя>-<версия>-rus.rbz`.
4. Всё. В течение часа релиз попадает в каталог, и у пользователей
   Exterminatus появляется кнопка «Update». Быстрее — Actions → catalog → Run
   workflow в репозитории Exterminatus.

Правила, от которых зависит обновление:

| Что | Почему |
|---|---|
| Версия в имени ассета (`-1.2-`) совпадает с версией в загрузчике | Exterminatus сравнивает их; `1.2` и `1.2.0` считаются равными |
| Суффикс языка `-rus` / `-eng` (или `-ru` / `-en`) | у пользователя ставится та же языковая сборка, что уже стоит |
| Релиз не черновик и не pre-release | черновики и пре-релизы пропускаются |
| Имя расширения (`SketchupExtension.new('RALNCS', …)`) не меняется | по нему Exterminatus находит установленный плагин |

Плохой релиз откатывается одной кнопкой «Roll back to …» в окне. Можно и
командой `PluginRollback <плагин>`: она ставит предыдущий релиз с GitHub.

## Как новый плагин попадает в список

Сам, ничего добавлять не нужно. Каждый час сборщик каталога перебирает все
публичные репозитории B-A-community и берёт репозиторий, если в нём:

- есть релиз версии **1.0 или новее**, не черновик и не pre-release;
- к релизу приложен `.rbz` или zip с `.rbz` внутри;
- внутри пакета загрузчик регистрирует `SketchupExtension`.

Из пакета сборщик берёт:

| Что | Откуда |
|---|---|
| имя расширения | `SketchupExtension.new('<имя>', …)` — строкой или константой (`EXTENSION_NAME = '…'`) из загрузчика или из файлов папки плагина |
| папка | имя загрузчика в корне пакета (`ralncs.rb` → `ralncs`) |
| описание | описание репозитория на GitHub |
| языки | суффиксы ассетов `-rus` / `-eng` |
| страница на pachka.space | страница сайта с тем же именем без дефисов (`ralncs` ↔ `plugins/ral-ncs/`) |

Репозитории без релиза 1.0, форки и проекты других программ (Rhino и т. п.,
без `.rbz`) в список не попадают. Релизы найденного плагина младше 1.0 не
показываются.

Найденный плагин встаёт в конец списка по имени. Чтобы задать ему порядок,
русскую подпись или описание, добавьте запись в
[`src/exterminatus/plugins.json`](../src/exterminatus/plugins.json) — это
уточнение, а не условие:

```json
{ "id": "section-slicer", "name": "Section Slicer", "repo": "B-A-community/section-slicer",
  "extension": "Section Slicer", "folder": "section_slicer", "description": "Horizontal sections by levels" }
```

| Поле | Значение |
|---|---|
| `id` | имя для команд (`PluginUpdate section-slicer`); у найденного — имя репозитория |
| `name` | подпись в окне |
| `repo` | репозиторий, только `B-A-community/…` |
| `extension` | имя расширения, как в Extension Manager |
| `folder` | папка плагина в Plugins (там `lang.rb`) |
| `description` | одна короткая фраза |
| `page` | страница на pachka.space, если её адрес не совпадает с именем репозитория |

## Страница на pachka.space

В окне Plugin Updates у плагина есть ссылки «pachka.space» (страница с
описанием, инструкцией и скачиванием) и «Reviews» (вкладка комментариев).
Вверху окна — ссылка на весь каталог.

Ссылку сборщик берёт из WordPress API сайта: страница плагина находится по
имени репозитория без дефисов и регистра (`area-counter` ↔ `plugins/area-counter/`,
`bevelchamfer` ↔ `plugins/bevel-chamfer/`). Если имена расходятся, задайте
`page` в `plugins.json`. Если сайт недоступен, каталог собирается без
ссылок. Открываются только адреса `https://pachka.space/…`, в браузере
пользователя.

## Как убрать плагин из списка

Зависит от того, что нужно:

| Ситуация | Что сделать | Что увидят пользователи |
|---|---|---|
| Репозиторий не плагин или не для всех (тест, черновик, внутренний инструмент) | тема репозитория `exterminatus-ignore` (GitHub → репозиторий → About → Topics) или строка в `hidden` в `plugins.json` | плагина нет в списке; у кого стоит, ничего не меняется, но и обновлений нет |
| Плагин больше не развивается или заменён другим | перевести репозиторий в архив (Settings → Archive) или запись в `retired` с причиной | новые не ставят; у кого стоит, видят «Retired» и причину, обновлений нет |
| Плохой релиз | удалить релиз или пометить его pre-release | релиз пропадает из списка; кто успел поставить, жмёт «Roll back» |
| Репозиторий удалён или стал приватным | — | плагин пропадает из списка при следующей сборке каталога |

Запись в `plugins.json`:

```json
"hidden": ["B-A-community/test-sandbox"],
"retired": [{ "repo": "B-A-community/old-tool", "reason": "Replaced by PathCopy Advanced" }]
```

Тема `exterminatus-ignore` и архив репозитория работают без правок в
Exterminatus: каталог учтёт их в течение часа. `hidden` и `retired` в
`plugins.json` начинают работать после пуша в `main`: Action пересоберёт
каталог сам.

Удалить уже установленный плагин с компьютера Exterminatus не может, это
делает пользователь в Extension Manager. Exterminatus только перестаёт его
обновлять и объясняет почему.

## Каталог и GitHub Actions

[`.github/workflows/catalog.yml`](../.github/workflows/catalog.yml) в
репозитории Exterminatus:

- раз в час, по кнопке и при изменении `plugins.json` запускает
  [`tools/build_catalog.rb`](../tools/build_catalog.rb);
- скрипт находит наши плагины (см. выше) и читает их релизы;
- кладёт `catalog.json` в ветку `catalog`.

Exterminatus читает каталог по адресу
`https://raw.githubusercontent.com/B-A-community/exterminatus/catalog/catalog.json`:
один запрос и без лимита GitHub API. Последний полученный каталог хранится в
`%APPDATA%\BACommunity\Exterminatus\catalog_cache.json`.

Если каталог недоступен, Exterminatus спрашивает релизы плагинов из
`plugins.json` через GitHub API. Найденные сами плагины этим путём не видны.
Если не отвечает и API, показывается последний сохранённый каталог.

Собрать каталог локально:

```bash
ruby tools/build_catalog.rb catalog.json
```

С токеном лимит API выше: `GITHUB_TOKEN=$(gh auth token) ruby tools/build_catalog.rb catalog.json`.
Определение плагинов на настоящих релизах проверяет
`ruby test/catalog_discovery.rb`.

## Что видит пользователь

- **Окно Plugin Updates.** У каждого нашего плагина видны установленная
  версия и язык, последняя версия и дата, что нового. Кнопки:
  - **Update** — есть новая версия;
  - **Install** — плагин не установлен; язык выбирается переключателем RU/EN
    вверху;
  - **Roll back to …** — вернуть предыдущий релиз;
  - **Update all** — обновить всё сразу.
- **Перезапуск.** Обновлённый плагин уже загружен в память, поэтому новая
  версия начинает работать после перезапуска SketchUp. Внизу окна появляется
  кнопка **Restart SketchUp**: SketchUp закрывается (спросив про несохранённые
  модели) и запускается снова. Новый плагин, которого не было, работает сразу.
- **Проверка раз в сутки.** Через 20 секунд после запуска SketchUp
  Exterminatus тихо проверяет обновления. Если они есть, он пишет строку в
  терминал и в строку состояния.
- **Команды в терминале:**
  - `Plugins` — список наших плагинов с версиями;
  - `PluginUpdate` / `PluginUpdate pathcopy` — обновить все или один;
  - `PluginInstall ralncs lang=en` — установить;
  - `PluginRollback ralncs` — откатить;
  - `PluginUpdates` — открыть окно;
  - `RestartSketchUp` — перезапустить SketchUp.

## Безопасность

- Скачивается только из релизов репозиториев B-A-community, только по HTTPS
  с GitHub. Каталог, в котором есть чужой репозиторий, чужая ссылка или
  небезопасное имя папки, этих записей не даёт: они отбрасываются.
- Каждый файл сверяется с размером и sha256, которые GitHub считает сам при
  загрузке ассета. Не совпало — плагин не ставится.
- Ставит пакет штатный `Sketchup.install_from_archive`, как Extension Manager.
- Выпускать релизы могут участники B-A-community, а любой новый публичный
  репозиторий организации с релизом 1.0 и `.rbz` сам попадает в список
  у всех. Значит, GitHub-аккаунты участников должны быть защищены
  двухфакторной аутентификацией, а заводить публичные репозитории — только
  тем, кто понимает, что они уходят пользователям.
- Если у пользователя в SketchUp включена политика «Identified Extensions
  Only», неподписанный плагин не загрузится. Такие релизы надо подписывать в
  Extension Warehouse, либо держать политику «Unrestricted».
